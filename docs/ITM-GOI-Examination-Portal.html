§1

Overview

The portal lets the examination cell run secured, invigilated online exams for students — creating question banks, building exams, locking the candidate's machine with Safe Exam Browser, watching every attempt live, and exporting results — all from one server on campus.

It is a standard Moodle 4.5 LTS installation, hardened for exams and extended with two purpose-built plugins:

  • local_examwizard — the exam cell's control centre: question uploader, a four-step exam builder, the Exam Control hub, live exam control, results export, bulk student onboarding, and the SEB quit-password manager.
  • local_sebkiosk — makes leaving Safe Exam Browser finalise the attempt, and carries the front-end theme runtime.

Contributed modules add webcam proctoring (quizaccess_proctoring), the SEB access rule (quizaccess_seb), and the Boost Union theme, which is skinned in the ITM Group of Institutions identity.

Design intent. Every exam is one attempt, one question per page, shuffled, time-limited, copy-protected, and — where required — only openable inside a locked-down browser with the webcam on. If a candidate's machine fails or they leave the browser, the attempt is submitted automatically and cannot be resumed.

§2

Architecture & technology

The platform runs directly on Windows as three Windows services plus a scheduled task — no containers. Docker was evaluated but its Linux engine does not start on the host machine, so the stack was ported to run natively.

LayerComponentNotes
ApplicationMoodle 4.5 LTS (MOODLE_405_STABLE)Web root at native/stack/moodle
Web serverApache 2.4 with mod_phpService eap-apache · port 8080
LanguagePHP 8.3 (Thread-Safe)OPcache, 512 MB limit, 100 MB uploads
DatabaseMariaDB 11.4 LTSService eap-mariadb · utf8mb4_unicode_ci
SchedulerWindows Task EAP-Moodle-CronRuns Moodle cron every minute as SYSTEM
ThemeBoost Union + custom Raw SCSSCompiled from config/moodle/custom.scss

Application data lives at E:\ASSESMENT\moodledata; all secrets and site settings are read from E:\ASSESMENT\.env. The database data directory and downloadable installers are excluded from source control.

§3

Setup & daily operation (no Docker)

The platform is a self-contained folder. Everything it needs — PHP, Apache, MariaDB and Moodle — ships extracted inside the repository, so setup is a git clone plus one script. No Docker, no separate installers. The server tier needs no internet during setup — only the Visual C++ 2015–2022 x64 runtime is fetched, and only if it is not already installed. The script derives every path from the folder it sits in, so the project can live on any drive.

3.1  What you need

  • Windows 10 (build 1809 or later) or Windows 11, 64-bit.
  • An account with local administrator rights — the setup script self-elevates via UAC.
  • Windows PowerShell 5.1 (ships with Windows); PowerShell 7 also works.
  • Git for Windows.
  • About 2 GB of free disk space — the repository carries the whole server stack.
  • Port 8080 free, or choose another with -Port.

3.2  Get the code

git config --global core.longpaths true
git clone https://github.com/Neerajparashar1/ASSESMENT.git C:\exam\ASSESMENT
cd C:\exam\ASSESMENT

The project path must contain no spaces, and should be short and not OneDrive-synced. C:\exam\ASSESMENT is fine; C:\Users\John Doe\… is not — the cron-task registration and the Windows service paths do not survive a space. Deep paths also hit the 260-character limit; OneDrive folders cause file-lock failures.

3.3  Exclude the folder from antivirus

Windows Defender and other antivirus tools occasionally quarantine part of the bundled server (a MariaDB or PHP executable) during the clone or during setup, which then fails in ways that are hard to diagnose. Before running setup, add the project folder as an exclusion:

Windows Security → Virus & threat protection → Manage settings → Exclusions → Add an exclusion → Folder — select the ASSESMENT folder.

If something was already quarantined, restore it from Windows Security → Protection history, add the exclusion, and clone again.

3.5  Run the installer

Open PowerShell in the project folder and run:

powershell -ExecutionPolicy Bypass -File .\native\Setup-MoodleNative.ps1 -Reinstall

On a different PC — always include -Reinstall. The repository carries a config.php and generated Apache / MariaDB configuration files with the original machine's paths and a machine-specific database. -Reinstall drops those and rebuilds every path, the database and the config for this machine. On the machine the repository was built on, run it without -Reinstall.

The script performs, in order:

  1. Installs the Visual C++ 2015–2022 runtime if it is missing (the one step that may need internet).
  2. Detects the bundled PHP 8.3, Apache 2.4, MariaDB 11.4 and Moodle 4.5 under native\stack\ and uses them as-is — it downloads a component only if it is genuinely missing (or you pass -RefreshBinaries).
  3. Generates php.ini, the Apache virtual host and my.ini — with this machine's paths.
  4. Initialises MariaDB, registers the eap-mariadb service, creates the moodle database and its user.
  5. Runs Moodle's non-interactive installer against <project>\moodledata.
  6. Installs the contrib plugins — Boost Union theme, proctoring, VPL.
  7. Writes the exam-hardening block into config.php (anti-cheat footer, autosave, proxied-SSL handling, the path to PHP).
  8. Runs post_install.php — theme and custom SCSS, SEB and proctoring defaults, quiz hardening, the Invigilator and Exam Hall Invigilator roles.
  9. Registers the eap-apache service, the one-minute EAP-Moodle-Cron task and a firewall rule for the port.
  10. Generates a starter .seb file from .env.

It prints the portal URL and the admin login when done, and is safe to re-run.

If you move the folder later, the generated Apache and MariaDB configs still point at the old location. Re-run Setup-MoodleNative.ps1 -Reinstall from the new location (this rebuilds the database), or hand-edit my.ini, Apache24\conf\httpd.conf, Apache24\conf\extra\httpd-eap.conf and native\stack\moodle\config.php, then re-register the services.

3.6  Apply the exam-specific configuration

These create the kiosk SEB template, ensure both invigilation roles, and compile the ITM theme. A -Reinstall already covers the roles and theme through post_install.php; run the SEB template script on every fresh machine, and re-run any of them after a related change.

set PHP=native\stack\php\php.exe
%PHP% native\Setup-SebLockdownTemplate.php --all
%PHP% native\Setup-InvigilatorRoles.php
%PHP% native\apply_itm_theme.php

3.7  Verify the installation

  • native\Manage-Moodle.ps1 status — both services Running, the cron task present, and an HTTP :8080  200 OK line.
  • Open http://localhost:8080 — the branded split-view login page appears.
  • Sign in as the admin. Site administration → Notifications should report no problems.
  • Site administration → Server → Environment — every row should pass.

3.8  Daily operation

Both services are set to start automatically, so after a reboot the portal is already running. Double-click start.bat to bring the stack up manually and stop.bat to take it down. The PowerShell wrapper native\Manage-Moodle.ps1 covers the rest:

CommandAction
statusService state and an HTTP probe
start / stop / restartControl the two services (needs an elevated shell)
cronRun one Moodle cron cycle now
purgePurge all Moodle caches
upgradeRun the Moodle upgrade after adding or updating plugins
import <csv>Bulk-import students from a roster
backupDatabase dump + moodledata archive to backups\

Grade export to ODS, XLS, TXT and XML is enabled site-wide from the gradebook.

3.9  Useful installer switches

  • -Reinstall — drop and rebuild the database, config and data directory (required on a new machine).
  • -Port 8888 — serve on a different port; also updates the portal URL.
  • -PhpSeries 8.2 — use PHP 8.2 instead of 8.3.
  • -RefreshBinaries — force a clean re-download and re-extract of PHP / Apache / MariaDB / Moodle (normally the bundled copies are used as-is).
  • -SkipPlugins — do not (re)install the contrib plugins.
  • -ApacheZip / -PhpZip / -MariaDbZip / -MoodleZip <path> — use a hand-downloaded build if a bundled one is missing or blocked.
  • -InstallRoot / -DataRoot <path> — place the stack or the data directory elsewhere.

§4

Exam Wizard toolkit In use

local_examwizard is a custom plugin built entirely on Moodle's supported APIs — the quiz engine and question bank are unmodified. Staff reach everything from one landing page, the Exam Control hub.

Question uploader

Upload questions as CSV, XLSX, GIFT, XML or plain text. Column headers are matched synonym-tolerantly. Before anything is imported, a visual preview renders every question as a card — green when valid, red with the specific error when not, correct options highlighted, with summary counts. Supports single-answer MCQ, multiple-response, true/false and short answer; GIFT and XML are handed to Moodle's own importers. Optional negative marking sets wrong options on single-answer MCQs to −⅓.

Four-step Create-Exam wizard

Basics → Questions → Rules → Review. It applies exam-sensible defaults — a time limit, automatic submission when time expires, deferred feedback, free navigation, results released only after the exam closes — forces a single attempt, and wires up Safe Exam Browser and proctoring in the same flow.

Exam Control hub

The operations home page:

  • At-a-glance counts — exams, students, subjects, and how many exams are live now.
  • An auto-detected getting-started checklist (branding, students, an exam, the SEB password, a test run).
  • Quick actions and a Your exams table with a status badge (live / open / scheduled / closed), an "in progress / submitted" count, and Monitor, Grades and "Get .seb" links per exam.
  • A Live-now spotlight — for each running exam: in-progress, submitted and not-started counts with a progress bar; the page refreshes itself every 30 seconds while an exam is live.

Live exam control

Steer an exam while it runs, without editing it:

ScopeActions
Whole examPause (close now) · Reopen for two hours · End & submit everyone
Per candidateEnd & submit now · Give +15 minutes (per-user override) · Resume an abandoned attempt · Delete attempt teachers only

Results & export

A per-candidate table — score, percentage, pass/fail, time taken, attempt state — with summary chips for attempted-vs-enrolled, average percentage and pass rate, and a one-click CSV download.

Bulk student onboarding

Upload a roster (CSV or XLSX). A validated preview shows which rows will create a new user and which already exist; on confirm it creates the missing accounts and enrols every valid row as a student. A default password field fills blank cells.

SEB quit-password manager

View or change the master Safe Exam Browser quit password, and optionally push it to every SEB-enabled quiz at once. The screen warns that changing it invalidates any .seb files already handed out.

§5

Safe Exam Browser lockdown

Applied to live exams Real-SEB smoke test pending

Exams that require it are opened only inside Safe Exam Browser, configured from the EAP Kiosk Lockdown template:

  • Windows kiosk — a fresh isolated desktop and the Explorer shell killed, so Task Manager, the Start menu and the taskbar are unreachable.
  • Every escape hotkey disabled — Alt+Tab, Alt+F4, Alt+Esc, Ctrl+Esc, Esc, F1–F12 and PrintScreen.
  • No application or user switching; a single display only; screen mirroring, virtual machines and screen sharing blocked.
  • The browser is URL-filtered to the portal host.
  • A Quit button is present and password-protected — the one sanctioned way out.

Leaving the browser submits the exam

The local_sebkiosk plugin turns any exit into a submission. The SEB Quit link and a page-unload beacon both call an endpoint that finalises every in-progress attempt for that student, so it can never be reopened.

Backstop for a hard kill. If a machine is powered off or force-quit mid-exam, the time limit plus automatic overdue submission plus the one-minute cron task submit the attempt when its time expires — nothing is left hanging.

Not tunnel-compatible. A live SEB attempt is bound to the server's real address and cannot run over a temporary demo tunnel (§10). Tunnels are for showing the portal and admin, not for taking a locked exam.

§6

AI proctoring

The quizaccess_proctoring module captures a webcam snapshot roughly every 30 seconds during an attempt, stores the images, and gives staff a proctoring review report alongside the quiz results. A face-present check runs when the candidate starts. No paid cloud face-matching service is used; review is by a person against the captured images.

§7

Roles & access control

Access is least-privilege. The site administrator is a single named account; everything else is a role assigned per course, per activity, or site-wide.

RoleCanCannot
Site administrator
examadmin		 Everything — the only account with full platform and server settings control. —
Invigilator / Proctor
faculty		 Build quizzes and question banks, manage SEB settings, run proctoring review, grade, run live exam control. Site administration.
Exam Hall Invigilator
hall staff		 Watch the monitor report and the live proctoring feed; run live exam control — pause, reopen, extend a student, force-submit, resume. Create or edit exams, edit questions, grade, delete attempts, reach site administration.
Student Sit the exams assigned to them. Everything else.

The hall-invigilator role is backed by a dedicated capability, local/examwizard:control, deliberately kept separate from Moodle's mod/quiz:manage so a proctor can steer a running exam without ever gaining editing rights. Assigned at site level, one login can oversee every exam session at once.

§8

Exam integrity & anti-cheat

One attempt

Every exam allows a single attempt; once finished it cannot be restarted.

Shuffled, paged

Questions are shuffled and shown one per page, with free navigation between them.

Clipboard blocked

Copy, cut, paste, right-click and drag are disabled on the attempt page; typing into answer fields still works.

Continuous autosave

Answers save every 15 seconds and on every page change, so nothing is lost to a disconnect.

Time-limit submission

When the clock runs out the attempt is submitted automatically, with no grace period.

Config-key gating

For SEB exams, the browser's configuration key is checked on every request — viewing, starting, each page and submitting — not only on quit.

§9

Interface & branding

The portal wears the ITM Group of Institutions identity — deep maroon and academic gold, the Inter and Source Serif typefaces, the official logo, and the “Think Big · Think Beyond” motto set in the institute's own kicker style.

  • Split-view sign-in — an auto-advancing campus slideshow with college information on the left, the login card on the right with assurance chips (locked-down browser, AI proctoring, instant result) and a support bar.
  • Home & dashboard — a branded hero band with the logo, the motto, a “Go to my exams” call to action and a security badge over a campus slideshow; a campus photograph fills the page margins; content blocks are styled as clean cards.
  • Available courses render as a responsive, colour-coded card grid with an initial-letter chip and a whole-card link.
  • Exam-taking screen — a distraction-free shell, a top progress bar, a question-navigator colour legend, a floating countdown that turns amber under five minutes and pulses red under a minute, and whole-option-card selection.
  • Responsive — the hero banners stack, the motto wraps, and hover-only cues drop on phones.

All static asset links are root-relative, so the site renders identically whether it is served from localhost or a temporary public address. Styling has one source of truth, config/moodle/custom.scss, compiled into the theme by native/apply_itm_theme.php; behaviour lives in local/sebkiosk/exam-ui.js.

§10

Sharing a live demo

The portal can be shown to someone off-campus over a temporary tunnel from the host machine, with no cloud hosting. Two paths are wired up:

MethodCommandTrade-off
Cloudflare demo-cf.bat  /  demo-cf-stop.bat Double-click, no account, no admin rights. Fresh random URL each run; quick tunnels can be flaky.
ngrok demo.ps1 -Domain <name>.ngrok-free.app  /  demo-stop.ps1 Needs a free ngrok account and a claimed static domain; the URL is then stable and reusable.

Both temporarily repoint the site at the public address and turn on proxied-SSL handling; the stop script restores localhost. Safe Exam Browser exams do not work over a tunnel (§5).

Security posture & open items

Indicative resistance to a determined candidate: on an institute-managed lab PC the setup is strong; on a student's own laptop it is good, with webcam proctoring carrying much of the weight in practice.

Open items
